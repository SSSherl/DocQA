# 发布验收测试清单

每次发布使用 `scripts/publish_release.py`：先运行单元测试，再生成干净 ZIP，解压到隔离目录启动服务，执行浏览器验收。任一步失败都不会生成发布通过标记。浏览器验收依赖 Playwright 和 Chrome（或已安装的 Chromium），Windows 密钥保存使用当前用户 DPAPI。

```powershell
python -m pip install pytest playwright
python scripts/publish_release.py
# 可选：使用自己的本机配置进行真实模型测试；只传配置路径，不传密钥。
python scripts/publish_release.py --live-config "D:\your-private-app\config.json"
```

真实模型测试会产生少量模型调用和费用。凭证只注入测试子进程环境，不写入发布包；未提供凭证时只测试本地模拟接口，报告会明确说明未测试真实平台。真实测试复用同一服务域名下的可用密钥，对预设六个角色分别检查；缺少该平台密钥的角色标记为停用，不算验证通过。临时文档、索引和浏览器均与个人工作区隔离。

## 自动验收

- ZIP 完整性及默认停用状态；不含个人配置、索引、加密凭证。
- 解压启动，导入 `examples/项目说明.md`，成功后清空文件框。
- 离线检索与回答具有真实示例文档引用；不存在的精确标识不伪造命中。
- 未允许远程调用时直接提示，不发送请求，不清空输入。
- 错误密钥、错误模型验证失败后保留输入，无绿色通过标记。
- “测试连接”成功只验证，不保存；“验证并保存”成功才写入加密凭证。
- 保存后星号占位，绿色勾位于“验证并保存”右侧；刷新后仍有已保存状态。
- 小眼睛显示、隐藏密钥；配置文件不含明文密钥。
- 替换密钥验证失败，保留原配置与原密钥。
- 手机宽度无横向溢出，浏览器无脚本异常。
- 提供私人配置时：真实模型连接、示例入库、两次带引用的模型回答。

## 手工测试问题

先在“文档知识库”导入 `examples/项目说明.md`。

| 输入 | 验收重点 |
| --- | --- |
| DocQA 由哪些模块组成？ | 回答包含模块，引用项目说明.md |
| FE_HEART_Start | 精确术语检索，可查看来源 |
| 文档和索引保存在哪里？ | 回答有依据且可追溯 |
| UNKNOWN_RELEASE_INTERFACE_999 | 不捏造不存在的接口说明 |

再检查 Enter 发送、Ctrl+Enter 换行、空白不发送、Markdown 标题与加粗、来源展开、停止生成与重新回答。云端生成相关检查需先保存自己的可用模型配置。

## 交付记录

发布目录的 `acceptance.json` 记录解压包验收结果和真实模型状态，`unit-tests.txt` 记录单元测试，`VERIFIED.json` 仅在全部已执行检查通过后生成，并绑定 ZIP 的 SHA-256。这证明本次检查时的结果，不代表服务商未来始终可用。没有真实平台凭证的发布应补做相应角色验证。

## 大文档与断联回归

发布流程还会在解压包中运行 `verify_import_resilience.py` 和浏览器导入测试，生成 `import-resilience.json`、`import-ui.txt`。使用合成的 147 页、17 幅矢量图 PDF，模拟失效代理环境、慢模型和截断响应，检查导入期间首页/状态/健康检查/任务接口保持响应；覆盖运行中服务重启、401 不重试、更新失败保留旧原文与索引、失败任务重启后一键重试和真实 PDF 页码引用。这些是本地故障模拟，不能代替特定云平台当时的可用性测试。

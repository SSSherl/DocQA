# DocQA 部署手册

适用版本：2026-10-26 发布版。系统为基于 AI Agent 的个人本地多模态文档智能问答工作台。

## 1. 发布包内容

解压 `DocQA-source-release.zip`，进入其中的 `DocQA` 目录。该目录包含程序、配置模板、合成示例、测试和本手册。

- 保留 DeepSeek、Gitee AI 的公开 URL、模型名、超时及向量维度，接收者无需重新抄写。
- 不包含 API 密钥、加密凭证、个人文档、解析缓存、索引、历史会话、本机虚拟环境或私人备份。
- 六个模型在运行配置中默认停用，远程调用默认关闭；页面“启用此通道”默认勾选，方便填完密钥直接验证并保存。默认勾选只是待保存的选择，不表示连接已验证或正在调用模型。
- 不配置 API 仍可导入文字资料，通过 BM25 检索并展示原文摘录；图片理解、语义向量、精排和模型综合回答需要对应服务。

## 2. 环境要求

- 推荐 Windows 10/11、Python 3.11 或更新版本，并确保终端能执行 `python --version`。
- 首次安装依赖需要联网。使用云端模型时还需能够访问相应服务。
- 不需要 Node.js、独立数据库服务或本机 GPU。Markdown、Mermaid 页面资源随程序提供。
- 推荐先在本机运行；当前服务绑定 `127.0.0.1`，不包含公网多用户账户和权限系统。

## 3. Windows 快速部署

将发布包解压到自己可读写的目录，例如 `D:\Apps\DocQA`，在该目录打开 PowerShell：

```powershell
python --version
.\start.ps1
```

如果终端阻止运行脚本，可为此次启动执行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\start.ps1
```

脚本会创建 `.venv`、安装依赖，并在不存在 `config.json` 时复制 `config.example.json`。看到启动地址后打开：

[DocQA 本地工作台](http://127.0.0.1:8765)

请保持启动终端运行。按 `Ctrl+C` 停止服务。下次仍可运行 `start.ps1`。

### 手动安装和启动

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e .
Copy-Item -LiteralPath config.example.json -Destination config.json
.\.venv\Scripts\python.exe -m docqa serve
```

已有自己的 `config.json` 时，跳过复制步骤，避免覆盖。

## 4. 在页面填写自己的 API

打开左侧“服务状态”，展开“高级选项”中的相应模型卡片。电脑双列布局下，同一行两张卡片同步展开或收起。

当前预设如下；模型名称、权限与收费以服务商控制台实际提供情况为准。

| 模块 | 服务基础 URL | 模型名 | 维度 |
| --- | --- | --- | --- |
| 问答 | `https://api.deepseek.com` | `deepseek-flash` | 不适用 |
| 图片解析 | `https://api.deepseek.com` | `deepseek-flash` | 不适用 |
| 语义检索 | `https://ai.gitee.com/v1` | `Qwen3-Embedding-8B` | 1024 |
| 结果精排 | `https://ai.gitee.com/v1` | `Qwen3-Reranker-8B` | 不适用 |
| 补充检索 | `https://ai.gitee.com/v1` | `bge-m3` | 1024 |
| 图文检索 | `https://ai.gitee.com/v1` | `jina-embeddings-v4` | 2048 |

配置顺序：

1. 在自己的 DeepSeek、Gitee AI 账户创建可用密钥，确认账户权限、额度与模型可用性。
2. 勾选“允许远程模型调用”。这会将必要的文档片段或图片发送至填写的服务，可能产生 API 费用。
3. 在问答和图片解析卡片分别填写自己的 DeepSeek 密钥；两处可以使用同一个账户密钥。
4. 在语义检索、精排、补充检索和图文检索卡片分别填写自己的 Gitee AI 密钥；同一平台可以重复填写同一有效密钥。不要把 DeepSeek 密钥填到 Gitee 接口中。
5. 勾选“启用此通道”，点击“验证并保存”，等待页面报告成功。只填密钥而不保存不会生效。
6. 配置完成后再导入文档。已有文档时，图片或向量模型变化会先重建临时索引，成功后再切换，可能需要等待并产生调用费用。

Windows 页面填写的密钥使用当前用户 DPAPI 加密，存放在 `%LOCALAPPDATA%\DocQA\credentials`，配置文件只记录凭证别名。密钥默认隐藏，以 `********` 占位，点击右侧眼睛可查看，再次点击隐藏。收起卡片也会隐藏。

留空表示保留已经配置的密钥，并非删除。需要清除时，勾选“清除已保存的密钥及环境变量绑定”，同时停用该通道再保存。

“测试连接”始终重新发最小请求，不保存配置；每个请求等待至多15秒，最多3个并发，不影响正式问答和入库的超时设置。成功结果可在5分钟内用于后续保存，接口、模型、维度或密钥改变后重新验证。仅修改向量模型时复用已有解析和引用，只更新相关向量；图片解析模型改变时才重新解析资料。“已配置”只表示存在启用的接口配置，不等于持续连通。请根据实际测试和调用结果判断。

### Linux/macOS 或使用环境变量

Windows 推荐直接使用页面输入框。其他系统的页面密钥加密存储不支持 Windows DPAPI，请使用环境变量，并在卡片的“高级配置”中绑定变量名。

例如在 Bash 中交互输入 DeepSeek 密钥，输入内容不会显示：

```bash
read -r -s -p 'DeepSeek API Key: ' DOCQA_CHAT_KEY
export DOCQA_CHAT_KEY
echo
python -m docqa serve
```

问答和图片解析两个卡片的“环境变量名”均填写 `DOCQA_CHAT_KEY`，密钥输入框留空，然后启用并保存。

Gitee 同理可以设置 `DOCQA_GITEE_KEY`，在四个 Gitee 模型卡片中绑定该名称。变量必须由启动 DocQA 的进程继承；新设环境变量后通常需要在对应终端重新启动服务。本程序不会自动读取 `.env` 文件。

其他系统手动安装示例：

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -e .
cp config.example.json config.json
python -m docqa serve
```

## 5. 导入文档与提问

1. 进入“文档知识库”，选择 PDF、DOCX、PPTX、Markdown、TXT 或图片；单文件最大 25 MB。
2. 可填写分类，然后点击“导入并建立索引”。
3. 页面显示读取 PDF、图片解析、文本向量、补充向量、图文向量和保存索引等阶段。任务提交后刷新页面可以继续查看，关闭浏览器不会取消服务器上的任务。
4. 导入成功后文件选择与分类输入框自动清空；失败时保留当前页面的输入，方便重试。浏览器刷新本身会重置文件选择。
5. 在“智能问答”输入问题：Enter 发送，Ctrl+Enter 换行。支持流式回答、停止生成、重新回答、Markdown、Mermaid 以及来源定位。
6. 点击引用可定位 PDF 页面；精确文本可高亮，图片解读仅提供真实页面和图片定位，不伪造文字高亮。

入库加速：图片解析和向量请求最多两个并发，文本向量每批最多8条；临时网络错误最多重试一次。成功的处理结果在本机缓存，失败重试可复用；同一文档与配置不变时直接复用现有索引。新文档首次导入仍取决于页数、图像数量和云端响应时间。

云端 `bge-m3` 通道为补充稠密向量，不等同于 BGE-M3 本地学习型稀疏通道。无需为了运行发布版下载本地模型。

### 使用自带测试文档

发布包包含 `examples/项目说明.md`，是公开的合成项目说明，不含密钥或私人资料。启动后进入“文档知识库”，选择该文件并导入，再到“智能问答”尝试：

- DocQA 由哪些模块组成？
- BM25 适合检索哪些精确术语？
- 云端 BGE-M3 和本地学习型稀疏检索有什么区别？

不填写 API 也可完成文字导入、BM25 检索和原文摘录验证；填写并验证模型后再测试综合回答。答案来源应指向“项目说明.md”及对应标题。测试文档不在首次启动时自动入库，需自行导入。

验证通过后，“验证并保存”按钮右侧显示绿色勾，收起卡片后标题处也有标记；修改配置或验证失败后会清除。该标记表示本页最近一次验证结果，不代表服务始终可用。

## 6. 常用命令

在项目根目录执行（Windows 将 `python` 替换为 `.\.venv\Scripts\python.exe`）：

```bash
python -m docqa serve
python -m docqa serve --port 8766
python -m docqa doctor
python -m docqa doctor --role chat
python -m docqa query "混合检索如何工作？"
python -m docqa ask "这个项目有哪些模块？"
```

自定义配置文件示例：

```bash
python -m docqa --config config.json serve
```

CLI 和页面读取同一份运行配置；保持在项目根目录运行。

## 7. 本机数据、备份与迁移

- `config.json`：本人的运行配置；不要与公开源码一起发布。
- `data/`：原文上传、解析图片、Markdown、SQLite 索引、会话和入库缓存；均属于个人数据。
- `data/ingest-cache.sqlite3`：模型处理缓存，不存密钥；清空缓存只会导致后续重复调用模型。需要清空时先停止服务。
- `%LOCALAPPDATA%\DocQA\credentials`：Windows 当前用户加密凭证；不放进公开发布包。

备份前先停止服务，保存 `config.json`、完整 `data/` 和需要的加密凭证。私人备份不要公开分享。不同 Windows 用户或电脑一般不能直接解密原用户 DPAPI 凭证，迁移时请重新填写自己的密钥。

索引记录包含本机原文件路径。换电脑部署时建议重新导入原始文档，不要假定直接复制旧索引后原文定位就能工作。

## 8. 常见问题

### 模型仍显示未配置

检查是否填写密钥、勾选启用、允许远程调用，并执行“验证并保存”。发布版预设 URL 和模型名不代表模型已启用。

### 401、403 或余额/资源不足

检查密钥所属平台和对应模型权限。401 通常与鉴权有关，403 也可能是权限限制，不能仅据此判断密钥无效。是否免费取决于服务商当前规则、账户资源和额度。

### 入库很慢或向量超时

查看具体停在哪个阶段。图片很多的 PDF 会逐页进行视觉分析；云端繁忙或网络不稳定时可能超时。修复网络或平台额度后重试，已经成功的处理结果会复用，不会自动关闭模型或用虚假向量替代。

### 端口被占用

不要随意结束其他应用。可以使用 `python -m docqa serve --port 8766`，然后访问对应的本机端口。

### 看到配置指纹变化、要求重建

优先通过页面“验证并保存”修改模型，由系统完成索引切换。手动修改配置文件后需要重启，并按提示重新导入或重建文档；仅重启不能自动修复不同模型之间的向量不一致。

### 后台监控暂无事件

未配置 `watch_dir` 时不会启动目录自动监控，不影响手动导入和问答。

## 9. 发布前检查

只分享本次生成的干净 ZIP 或其中的 `DocQA` 目录。ZIP 内有 `RELEASE-MANIFEST.json`，发布目录另有 SHA-256 和核验记录。不要将运行后产生的 `config.json`、`data/`、`.venv/`、加密凭证或私人备份重新打包分享。

验证失败时输入会保留，错误原因在对应卡片内显示。测试连接成功不等于已保存，请再点“验证并保存”；保存成功后输入框以星号占位，刷新后仍显示“密钥已保存”。验证步骤与测试问题见 [验收测试清单](验收测试清单.md)。

## 大文档导入与网络（本次修复）

模型 HTTP 请求默认直接连接平台，不读取 Windows 系统代理或 HTTP_PROXY、HTTPS_PROXY、ALL_PROXY；无需配置代理。流式问答也使用直连。不修改操作系统的代理设置。若网络必须经过代理，请使用可直接访问的模型网关地址；此版本不提供通用代理开关。

网页上传在独立进程内解析、调用模型并提交索引，期间网页与轻量 `/api/health` 仍可访问。重启网页服务不会取消已启动的导入进程；进度保存在本地，刷新可继续查看。模型配置和另一份导入不能与当前导入同时执行。

导入失败会保留原文件和旧索引，并显示“重试导入”。点击即可重试最近的失败任务，无需重新选择文件，成功处理过的模型结果会复用。任务状态及失败原件位于 `data/import-jobs/`，正式原件仍在 `data/uploads/`；这些均为个人数据，不应加入发布包。成功后删除任务中的重复原件和临时凭证配置。更新已有文件时，原件在新索引准备好之前保持不变。

所有已启用向量计算成功后才提交完整索引，失败不会自动禁用模型，也不会用关键词检索或假向量冒充云端模型。新文档在提交前仍不计入知识库数量，请结合导入阶段和进度判断。暂未实现逐块发布索引或跨机器断点迁移。

默认 Embedding 超时 120 秒、BGE 90 秒、图文 120 秒；模型连接验证仍使用较短的探测超时。可按平台情况在各通道高级配置调整。批处理参数可在 config.json 设置：

```json
"ingestion": {
  "batch_size": 8,
  "workers": 2,
  "retries": 2,
  "retry_backoff": 0.5
}
```

批量范围 1–32，并发 1–4，重试 0–3，退避初始值 0–10 秒。仅对超时、连接中断（含响应截断）、临时服务错误重试，等待时间逐次翻倍；错误密钥和限流不会自动重试。平台批量请求容易超时时，可减小 batch_size 或 workers。参数变化可能导致部分批次缓存不能复用，但不改变模型语义。

PDF 页数、图表数量、文本块数量和平台速度决定导入时间，文件体积小不代表调用少。当前 25MB 限制仍保留，支持多页 PDF，未按固定页数拒绝导入。

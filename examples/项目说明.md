# DocQA 项目示例资料

## 系统架构
DocQA 由 doc2md 文档解析层、DocBase 检索层、Agent 问答层组成。Web 界面是本地入口；后台 Service 监控指定目录并增量更新索引。

## 三路混合检索
DocBase 可以组合 BM25 关键词检索、Qwen 稠密向量和 BGE-M3 补充稠密向量三路召回；启用图文向量后还可检索文档图片。召回结果通过 RRF 融合，再由 Reranker 精排，输出 TOP-K 文本块，由问答模型整理回答。

云端 bge-m3 的补充稠密向量不等于本地学习型稀疏向量；本地学习型稀疏检索需要另外安装组件和真实模型权重。BM25 适合 SD5993、FE_HEART_Start 等精确术语。本测试资料仅用这些字符串演示关键词检索，不提供真实型号或接口的业务含义。未配置模型时只启用 BM25，不具备模型语义检索能力。

## 部署步骤
第一步运行 start.ps1，创建 Python 虚拟环境、安装依赖并启动本地 Web 工作台。首次运行从 config.example.json 创建 config.json。第二步根据需要在“服务状态”填写自己的密钥，验证并保存；不配置 API 也能进行文字资料的 BM25 检索。第三步在“文档知识库”导入本文档。第四步切换到“智能问答”提问。

## 数据与来源
文档、解析 Markdown、图片和 SQLite 索引存储在 data 目录。默认不允许把文档发到远程模型。回答应保留文档名、页码或标题、图号以及引用编号。Word 使用标题定位，不生成虚假页码。

## 测试方法

本文档是可公开分享的合成示例，不包含个人资料或 API 密钥。它用于验证文字资料导入、检索、引用与可选的模型综合回答，不用于证明图片或 PDF 定位效果。

导入后可以依次提问：

- DocQA 由哪些模块组成？
- BM25 适合检索哪些精确术语？
- 云端 BGE-M3 和本地学习型稀疏检索有什么区别？
- 文档和索引保存在哪里？

未配置 API 时，应展示与问题相关的原文摘录和“项目说明.md”的标题来源。配置并验证对应模型后，可以进一步测试语义检索、精排和综合回答。
